# 澄文扫描台 · DocScan

浏览器里跑的扫描件修复工具：把手机拍的公文、合同、票据**漂成白纸黑字**，同时**保住红头、印章和彩色批注**，最后拼成体积可控的位图 PDF。

全部处理在本地完成，不上传任何文件，没有后端，没有构建步骤，没有运行时依赖（`node` 只用来提供一个静态文件服务）。

## 它要解决的问题

普通"扫描件增强"最容易被忽略的不是"够不够白"，而是**内容有没有被算法悄悄改掉**：

- 二值化把红色公章压成黑块，页面看着完整，红头已经不是红的了；
- 去噪把小字号笔画、表格细线、印章环形文字抹掉；
- 有损压缩（如 JBIG2）把相似字形合并，压完出现错别字，事后无法判定；
- 预览用的是一套参数，导出时又按"当前全局设置"重算一遍，所见非所得。

本工具围绕这几条做取舍：漂白走 1-bit + Flate 无损，印章走独立彩色掩膜，灰度/彩色页走连续调不二值化，每页保存自己的参数快照，导出后回读全部页面自检。

## 环境要求

| | 要求 |
|---|---|
| 浏览器 | Chrome / Edge 90+（推荐）、Firefox 113+、Safari 16.4+ |
| Node.js | 16+（仅用于启动本地静态服务，可不装，改用 Python） |
| Python | 3.x（可选，`python -m http.server` 兜底） |

> 浏览器门槛主要来自 `CompressionStream` / `DecompressionStream`。缺少它们时程序不会崩：1-bit 页会退化成 JPEG，同时**无法做无损回读校验**，状态栏不会出现"无损校验通过"。重要档案请用支持的浏览器。

**必须通过 HTTP 打开，不能双击 `index.html`。** 直接 `file://` 打开时，PDF.js 的 worker 会被同源策略拦住，导致 PDF 导入失败、导出自检被跳过。

## 启动

```bash
# 方式一（推荐）
node serve.js            # 然后访问 http://127.0.0.1:8765/

# 方式二：Windows 双击
serve.bat

# 方式三：任意静态服务器
python -m http.server 8765 --bind 127.0.0.1
```

服务只监听 `127.0.0.1`，局域网内其它机器访问不到。

## 使用流程

1. 拖入图片（JPG/PNG/WEBP/PDF，可多选，PDF 自动拆页）。
2. 左侧选增强模式：
   - **漂白**：白底黑字，红头与印章仍为红色（默认）；
   - **灰度**：保留照片层次的连续调；
   - **彩色**：只做有限光照校正，最大限度保真。
3. 按纸张状况选档（标准／干净／淡墨／污渍／阴影），必要时再微调滑杆。
4. 需要手工修边时点「调框」，拖四角贴合纸张边缘。
5. 「导出 PDF」（带书签、全页回读自检）或「导出图片 ZIP」（按页选 PNG/JPEG）。
   - 默认文件名取**源文件名**：源是 `原件.pdf` 就导出 `原件.pdf`，不再加 `_扫描版` 后缀。
   - 在 Chrome / Edge 里**拖入或点选**文件会拿到源文件句柄，导出时可直接**覆盖源文件**（覆盖前会确认）；系统另存对话框可用时优先用它，否则退回普通下载。
   - 导出成功后自动清空工作栏（文件查阅栏）；也可以随时点「清空任务」手动清空。

## 参数自动记忆

所有界面设定会在改动后自动存进浏览器本地（`localStorage`），**刷新页面、关掉浏览器再打开、重启电脑，都沿用上次的设定**，不用每次重新勾一遍。

记住的范围：

- **处理参数**：增强模式、纸张状况、六个滑杆、保留红头/印章、检测纸张边缘、去除边缘黑边、清理折痕/杂线、对开页拆分、自动纠偏、断笔接续、裁去白边
- **输出设置**：处理分辨、单页体积、页面尺寸
- 导入的文件与处理结果**不保存**——关掉页面就没了，这是有意的（文件太大，也不该占浏览器存储）

几点行为说明：

- 改动即时生效，落盘有 200ms 合并；直接关标签页时会在页面卸载前补写一次，拖完滑杆立刻关也不会丢。
- 「重置」按钮会把**全部**参数（含开关和下拉）恢复默认，并把默认值存为下次的设定。原来它只重置滑杆。
- 存储按「协议+主机+端口」隔离。用 `http://127.0.0.1:8765` 和 `http://127.0.0.1:8766` 打开是两套独立设定；换端口后需要重设一次。
- 隐私模式、或浏览器禁用站点存储时，保存会静默失败——功能照用，只是记不住，不报错不阻塞。
- 存档损坏或含非法值（手改过、旧版本残留）时按默认值降级：滑杆值超出范围会被夹到区间内，下拉里不存在的值会被忽略。

想彻底清掉记忆：浏览器开发者工具 → Application → Local Storage → 删除 `docscan.settings.v1`（或清除该站点数据）。

## 参数速查

| 参数 | 作用 | 什么时候动它 |
|---|---|---|
| 漂白强度 | 整体提亮与白底地板 | 纸面发灰时上调；字被漂淡时下调 |
| 文字加深 | 墨量曲线指数 | 字偏细、发虚时上调 |
| 去阴影 | 光照场归一化强度 | 拍歪有手影/台灯光斑时上调 |
| 局部对比 | 影响 Sauvola 的 k | 字与纸反差小、糊字多时上调 |
| 去噪点 | 孤立连通域清理强度（0/1/2） | 复印噪点多时上调；细表格多时保持 1 |
| 锐化 | 对墨量做非锐化掩模 | 缩印件发糊时轻调 |
| 纸张状况 | 局部阈值的窗宽与系数（五档） | 先选档再微调，比直接拉滑杆稳 |
| 保留红头/印章 | 彩色像素单独成层 | 纯黑白归档可关掉以减小体积 |
| 检测纸张边缘 | 自动找四角做透视校正 | 已经裁好的平板扫描件可关掉，省一步也可能更准 |
| 对开页拆分 | 摊开的书刊自动拆成左右两页 | 单页素材/已是单页的图关掉，避免误拆 |
| 断笔接续 | 小字笔画断裂时做邻域补偿 | 缩印件、传真件字断时开；正常件保持关，开了字会变粗 |
| 单页体积 | 1-bit 页放大上限 / JPEG 质量搜索 | 移交要求严格时选 80–150KB |

## 自检与验证

```bash
node tools/selftest.js      # 10 项内核断言，纯 Node，无浏览器依赖
```

覆盖：细线保护、灰度/彩色的中间调与色相、连续调不改像素、实心块墨量守恒、多色页红蓝共存、泛黄纸不被整页判墨、五档出墨顺序、极端尺寸不崩溃。

界面侧的人工验证（约 5 分钟）：

1. 打开页面，点「载入示例」。示例页含红章与蓝灰照片，状态栏应显示 `JPEG · 多色页回退连续调`，而不是单色 1bit。
2. 导入一份纯文字页，导出 PDF：状态栏显示 `1bit · 无损校验通过`，提示"已导出 N 页 · 校验通过"。
3. 导入一份红头页（保色开启），导出 PDF：红头/印章仍为红色，状态栏显示 `红头/印章单层保色`。
4. 导出图片 ZIP：纯黑白页是 1 位 PNG（同一页通常只有几 KB~几十 KB），彩色页是 PNG，灰度页是 JPEG；逐页打开确认内容不重复。
5. 打开开发者工具控制台，确认没有报错。

## 已知限制与风险

以下都是**已知且有意保留**的行为，使用前请对照：

1. **灰度/彩色页会保留中间调**，这是修复目标而非缺陷；代价是体积比纯黑白页大一个数量级。
2. **开启保色时，明显的彩色污渍也会被保留**。要"绝对干净的白纸"，请关闭「保留红头/印章」。
3. **1-bit 页的逐字节无损保证**（Flate + 回读比对）只覆盖黑白层和印章掩膜；灰度/彩色/多色回退页用的是 JPEG，属于有损编码。
4. **多色页会整页回退成 JPEG**：一页上同时存在两种以上颜色时，为不猜主色而放弃 1-bit，体积会明显变大。状态栏会标注「多色页回退连续调」。
5. **很小的彩色内容会被忽略**：彩色像素占比低于 0.03% 时不单独成层（避免把压缩噪点当印章）。发丝级彩色标注可能并入黑白层。
6. **彩色页的 PNG 体积偏大**：图片 ZIP 里的彩色页是 24 位 PNG（含 alpha 通道），一页几百 KB 很正常。需要更小体积请走 PDF。
7. **整页极暗的扫描件（如全黑底片）可能被判为空白**：算法假设"纸比字亮"。这类件请先用灰度模式确认内容。
8. **自动四角、对开拆分、装订阴影、极端淡墨具有样本依赖性**，合成测试通过不代表所有真实件都安全。重要档案请保留原始扫描件，处理版不要替代原件。
9. **内存随页数线性增长**：每页保留源图、校正图和结果图。几十页以上建议分批导入，处理完一批先导出。
10. **不做 OCR**，输出是位图 PDF。需要文字层时，导出后用 `ocrmypdf --skip-text in.pdf out.pdf` 套一层透明文字。
11. **EXIF 方向依赖浏览器**：现代 Chrome/Edge/Firefox 会自动应用手机照片的旋转标记；极老的浏览器可能导入后方向不对，用「旋转」按钮修正。
12. **"覆盖源文件"只在 Chrome / Edge 生效**：浏览器只在拖拽或 `showOpenFilePicker` 时才交出文件句柄。Firefox / Safari 没有这套 API，导出退回普通下载（文件名仍与源一致，但需你手动放回原目录）。另外「导出图片 ZIP」是打包结果，无法覆盖单张源图。
13. **输出的不是 24 位彩色图像**：黑白层是 1bit `DeviceGray`，印章是 1bit `ImageMask` 加专色填充。红头、印章颜色真实、可打印，但按「色彩位数不低于 24 位」的进馆口径不算彩色扫描件。正式移交档案馆时请另行保留彩色原件（TIFF/JPEG，≥300dpi），本工具输出宜作检索与传阅副本。
14. **2000px 档低于档案行业标准底线**：DA/T 31—2017 第 9.4.2 条要求扫描分辨率不小于 200dpi。3508px ≈ A4 300dpi、2600px ≈ 222dpi 均达标，2000px ≈ 171dpi **不达标**，只宜用于屏幕阅读或内部传阅。
15. **导入端有 3000px 上限**（`app.js` 的 `SOURCE_MAX`）：长边超过 3000 的源图会先降采样再处理。因此即便选 3508px 档，若源图长边大于 3000，最终是「降采样后再插值放大」，并未保留源图的全部像素。要严格保留 300dpi 原生细节，需把 `SOURCE_MAX` 提到 3508 以上（代价是每页内存从约 25MB 升到约 35MB）。
16. **PDF 导入固定按约 200dpi 渲染**（A4 宽 1654px，`app.js` 的 `pdfToCanvases`）。导入 300dpi 的 PDF 会先降到 200dpi 再处理，细节有损失；需要 300dpi 存档时，应直接导入原始 JPG/PNG 图片，而不是 PDF。

## 目录结构

```
index.html        界面结构 + 算法说明（「规范与算法」弹窗）
styles.css        样式
core.js           图像内核：四角检测 / 透视 / 纠偏 / 光照 / 二值化 / 保色 / 去噪
pdfout.js         PDF 组装、1-bit Flate 编码、印章掩膜、JPEG 预算搜索、ZIP
app.js            交互层：导入、逐页处理、参数快照、导出与自检
demo.js           合成示例（红头文件 + 手机拍摄效果）
serve.js          零依赖静态服务（仅 127.0.0.1）
serve.bat         Windows 一键启动
tools/selftest.js 内核自检（node tools/selftest.js）
vendor/           PDF.js 3.11.174（本地内置，不联网）
samples/          两份可复现的样例 PDF
```

## 第三方组件与许可

- `vendor/pdf.min.js`、`vendor/pdf.worker.min.js`：Mozilla **PDF.js 3.11.174**，Apache License 2.0，文件头保留了完整许可声明，未做修改。
- 其余代码为本项目自研。算法出处已在 `core.js` 顶部与相关函数注释中标明：
  - Sauvola & Pietikäinen, *Adaptive document image binarization*, PR 2000；
  - Wolf & Jolion, *Text localization, enhancement and binarization*, ICPR 2002；
  - 马健《ComicEnhancerPro》系列实践（先放大再二值化、墨量守恒、MRC 分层）；
  - 翁志艺《PDF 补丁丁》（重压缩准入条件、结构与渲染双层自检、按文件名生成书签）；
  - ScanTailor 的 "divide by background" 去底色思路。
  
  这些是**思路借鉴与独立实现**，没有直接复制上述项目的源码；论文公式与通用算法（积分图、Otsu、凸包、CRC32 等）属于公有领域实现。
