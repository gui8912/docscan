规范依据与处理流程

一、这是怎么处理的

  1. 纸张四角检测：光照归一化后用 Otsu 分出纸面，取最大连通域，凸包 + 极值点求四角，再以最小外接矩形兜底（可手动微调）。
  2. 透视校正：单应矩阵反算，双线性重采样，把斜着拍的纸拉成正面矩形。
  3. 去阴影 / 抹平底灰：对灰度做形态学闭运算估计“光照背景”，再逐像素做除法归一化。漂白页执行完整校正；灰度/彩色页只做有限增益，并按最亮颜色通道防止截断，避免把照片中间调和大面积色块误当阴影漂白。
  4. 自适应二值化：Sauvola 变体，按局部均值与标准差取阈值，小字、糊字不会被一刀切死；再用低墨量地板阈值把残影清零，得到真正的纯白。
  5. 保色通道：对色度（chroma）显著且饱和度够高的像素单独走彩色分支，保持色相、提升纯度，因此红头、红章、蓝笔批注不会被二值化吃掉。
  6. 强制暗线的例外：局部阈值的阈值恒低于局部均值，任何“大片均匀色块”（照片、粗标题、实心印章）都会被判成背景而整块翻白。因此对“局部背景本身也暗”的区域加一条绝对暗线兜底；限定“背景也暗”是为了不盖掉各档位与滑块的差异。
  7. 去噪 / 锐化：删除孤立小连通域（不侵蚀笔画），对墨量做非锐化掩模，笔画更实更黑。
  8. 断笔接续（2.4.7 重写，默认关）：沿 0° 横、90° 竖、±45° 撇捺四条方向线找「实心墨 ≥2px → 短断口 → 实心墨 ≥2px」，只在留白像素上补一段两端略强、中间略弱的软过渡墨；断口上限常规 2px（300dpi 仿宋笔画宽 4~6px、字间距 ≥8px，上限很安全），只有笔画芯部仅剩 1px 的极小字降到 1px，增强档 3px。实机回归：46px 仿宋样本挖出 442 个 2px 断口，关闭档与旧版档补上 0 个，公文·仿宋档与增强档补上 442 个；误补的留白像素公文档约 0.19%、增强档约 0.60%。注意仿宋笔画本来就细，不能拿「笔画细」当「分辨率低」去压上限 —— 这一版踩过两次坑才定稿。旧版只遍历已有墨迹像素、用 3×3 全向最大值把淡墨提亮，纯白断口根本没被处理，却把笔画末端朝四面一起拉粗 —— 这正是「开了字变粗、断口还在」的原因。现在不整体加粗笔画，交叉处也不会被方形核糊住。它补的是扫描 / 二值化造成的 1~2px 断口，不造新笔画、不改字形；上限远小于中文字间距，也不磨圆仿宋起收笔的斜势棱角与撇捺尖峰。
  9. 对开页拆分：整幅横向图先找中缝（列梯度最宽的空带），再验证左右两半“各像一页”（版心居中），确认后拆成两页并各自重新取景。
  10. 成册：黑白页用 1bit 位图 + Flate 压缩，并按剩余体积预算放大后再二值化；放大的长边上限就是“处理分辨”档位——3508 档按 A4 300dpi 排版，2600 档约 222dpi，2000 档约 171dpi。灰度/彩色页用 JPEG 按目标体积二分搜索质量。多文件导入时按来源文件自动生成书签大纲。
  11. 印章分层：漂白模式下，红头/印章的彩色像素从黑白层里摘出来，单独压成一层 1bit 掩膜，在 PDF 里用填充色画在黑白层之上 —— 页面仍是 1bit、仍能保持 300dpi，但红色不会变成黑块。掩膜同样做“墨量守恒”反算（否则放大后章名细笔画会碎成点），再补一道 1 像素形态学闭运算接断笔。2.4.6 修正了这道闭运算的跨字节取位：原先会在每 8 像素的边界凭空多出一列墨，现与逐像素 3×3 形态学完全一致。
  12. 导出后自检：PDF 生成后立刻用 PDF 解析器回读一遍——结构层核对页数，渲染层把每一页都真的画出来；两层都过才提示“校验通过”。
  13. 导出与落盘：文件名默认取源文件名（源是 原件.pdf 就导出 原件.pdf，不再加“_扫描版”后缀）。在 Chrome / Edge 里拖入或点选文件会同时拿到文件句柄，导出时可直接写回原路径覆盖源文件；覆盖前会弹确认，而这一步不可撤销，重要原件请先自己备份。Firefox / Safari 没有这套接口，自动降级为“另存（建议名 = 源名）→ 下载”，文件名仍与源一致，但要你手动放回原目录。导出成功后工作栏自动清空；只有保存链路彻底失败时才保留工作栏供重试。
  14. 无损回读校验（三态）：1bit 图像压成 Flate 后立刻解压回来逐字节比对。true = 完全一致；false = 解压失败或字节不符，直接阻止导出；null = 当前浏览器没有解压接口，只能提示“未回读校验”，不阻断。2.4.6 之前把“解压抛错”误当成“验不了”，一条被改坏的压缩流可以凭这个空子混过拦截。

一点五、纸张状况这五个档位

局部二值化的效果几乎全由“窗宽”和“系数”两个参数决定。这里的五档来自书格社区公开的实测预设，但不能照抄数值：Wolf 与 Sauvola 的系数方向相反——Sauvola 的阈值是 t = 均值 × (1 + k × (标准差/128 − 1))，k 越大阈值越低、出墨越少。所以“淡墨”要调小 k，“污渍”要调大 k 并放大窗口。五档都按此换算并实测校准过。

实测（合成淡墨页，笔画仅比纸暗 62/232）：淡墨 4.88% > 干净 2.14% > 标准 0.35%。而笔画很实的页面五档结果一致——档位只对“临界”情况起作用，这正是它该有的行为。

一点六、中文公文（仿宋）与「圆润」从哪来

先厘清一个词：笔顺是书写笔画的先后顺序，位图扫描件里并不存在、也谈不上修复；这里讨论的是笔画形态 —— 断口、边缘过渡与连接观感。按 GB/T 9704—2012《党政机关公文格式》，正文一般使用三号仿宋体字。仿宋的特点是各笔画等粗、起笔收笔带斜势棱角、折笔棱角分明、点撇捺挑勾的尖峰较长，与宋体「横细竖粗 + 几何衬线」不同。这决定了两件事：① 全向方形膨胀会抹平尖峰、糊住笔画交叉处，是仿宋最忌讳的处理；② 「把笔画磨圆」本身就是改字形，不该做。

圆润感的真正来源是中间调，不是把笔画磨圆：1bit 位图没有灰阶，边缘只能是硬阶梯。本工具用「先放大再二值化」把边缘落到亚像素位置（见第二节），再用 Flate 无损保存；若要更接近印刷观感，请切到灰度 / 彩色连续调模式并选 3508px 档 —— 灰度保留笔画边缘的抗锯齿层次，观感最圆润。断笔接续只负责把断口补成连续的一笔，补的墨量低于笔画芯部，1bit 阈值后呈细腰，视觉上像运笔的提按而不是一根方棍。

保真边界（务必留意）：DA/T 31—2017 第 4.3 条要求「真实反映档案内容，最大程度地展现档案原貌」，第 10.4 条要求去污不得去除页面原有痕迹；各地进馆与采购口径还常写有「不得出现字迹笔画残缺或字迹笔画叠合而影响阅读」「图像为扫描所得、不得为通过软件运算加工所得」。补断口属于对内容的主动修补，因此保持默认关闭，并保留「旧版」档供对比与回退；建议只用于自用、传阅或打印副本，存档母本请保留原始彩色扫描件。本工具面向个人自存，不是专业档案机构的进馆加工流程；正式移交请以档案馆的具体要求为准。

二、为什么默认 150KB / 页

DA/T 31—2017《纸质档案数字化规范》：扫描分辨率不小于 200dpi，文字偏小、密集、清晰度较差时建议不小于 300dpi；并明确 “页面中有红头、印章或插有照片、彩色插图的档案，应采用彩色模式进行扫描” —— 这正是本工具“漂白但保留红头印章颜色”的规范依据。

各地档案进馆的执行口径普遍是：黑白二值 A4 单页 20–40KB，灰度或彩色 A4 单页 100–300KB，彩色 PDF 单页上限 500KB。本工具默认 150KB，落在“彩色 100–300KB”区间中部，既满足移交要求，又便于微信/邮件传输。

若只是内部传阅，选 80KB 更省流量；若需长期存档或打印，选 300KB 或不限制，并把处理分辨调到 3508px（A4 300dpi）。2600px 约合 A4 222dpi，满足 DA/T 31—2017 的“不小于 200dpi”底线；2000px 只有 171dpi，低于该底线，不要用于存档。

但要先说清一个上限：导入时原图长边会被压到 3000px 以内（A4 约合 257dpi），所以 3508 档输出的是 300dpi 的版式，细节上限仍约 257dpi —— 不可能凭空长出源图没有的信息。要尽量接近 300dpi，只有两条路：直接导入未压缩的原始 JPG/PNG（别走 PDF，PDF 导入会固定按约 200dpi 渲染），并且拍照/扫描时就用 300dpi 以上。对个人自存与 A4 打印，257dpi 已经够用；正式移交进馆请按档案馆要求另行扫描。

存档提醒：DA/T 31—2017 第 9.3.2 条明确“页面中有红头、印章或插有照片、彩色插图、多色彩文字等的档案，应采用彩色模式进行扫描”，所以红头文件务必勾选“保留彩色”。同时注意：本工具输出的是 1bit 位图 + 印章掩膜，并非 24 位彩色图像；而各地档案馆进馆普遍要求“彩色 300dpi、色彩位数不低于 24 位、保存级用 TIFF 无损”。正式移交请另行保留彩色原件，本工具的输出宜作为检索、传阅与日常调阅副本。此外，规范第 10.3 条要求裁边“距页边最外延至少 2 至 3 毫米”，第 10.4 条明确去污“不得去除档案页面原有的纸张褪变斑点、水渍、污点、装订孔等痕迹”——这两条是“去黑边”与“漂白”的合规边界，清得过头反而破坏原貌。

导出时若体积预算还有富余，1bit 位图会自动放大到更高像素密度再二值化——这不是“注水”，而是用亚像素重采样换取平滑轮廓：1bit 图像放大后出现的毛刺、粘连、断笔，根源就是边缘没有中间灰度，先放大再过阈值能从源头缓解（此经验来自马健 ComicEnhancerPro 长期实践）。放大倍率受“目标墨量”约束，笔画粗细与原尺寸保持一致；放大的长边上限跟随“处理分辨”档位，所以选 2000 档不会再被放大回 3508，选小档确实能得到更小的文件。

三、关于“文字 PDF”

本工具输出的是位图 PDF（图像型），不做 OCR，因此 150KB 的目标是靠“1bit 压缩 + 分辨率控制”达成的，而不是把文字抽成文本层。位图 PDF 的好处是版式、印章、手写批注 100% 还原，任何终端打开都不会跑版。

如果确实需要可检索的文字层，建议在导出后再用 OCRmyPDF 套一层透明文字（ocrmypdf --skip-text out.pdf final.pdf），体积只会增加几十 KB。

四、关于“真实性”

扫描件的“真实性”不只是看起来清楚，还包括内容有没有被算法悄悄改过。这一行有个著名的坑：有损 JBIG2 压缩会在“相似即相同”的符号字典里把不同的字合并，压完可能出现错别字甚至丢内容，而且事后除了与原件逐像素比对，没有任何技术手段能判断某页到底是有损还是无损压缩。

本工具只使用 Flate（zlib）无损压缩，并且每次编码后都把压缩流解回来与编码前的位图逐字节比对（印章掩膜也一并验），通过后状态栏会显示“无损校验通过”。也就是说，导出文件里的每一个像素都能溯源到处理结果，不存在“看着一样、其实改过”的余地。

另一类“不真实”更隐蔽：所见非所得。二值化把红色压成黑块，页面看着完整，红头却已经不是红的了。本工具在导出时会把彩色像素单独成层，因此预览里是什么颜色，PDF 里就是什么颜色；若一页上同时存在多种颜色（彩色插页、多色批注），则自动退回彩色 JPEG，不做单色化猜测。

导出图片同理：纯黑白页存 1 位 PNG（无损，一页约 17KB，比 24 位 PNG 小 16 倍）；带红头/印章的页存 24 位 PNG 以保住颜色，代价是体积大得多。纯黑白图绝不能存 JPG——JPEG 会在笔画边缘糊出一圈灰，属于典型的“看着一样、其实改过”。要兼顾体积与保色，请用 PDF。

五、参数会自动记住

所有界面设定在改动后自动存进浏览器本地（localStorage 里的 docscan.settings.v1），刷新页面、关掉浏览器再打开、重启电脑，都会沿用上次的设定——包括增强模式、纸张状况、六个滑杆、保留红头/印章、检测纸张边缘、去除边缘黑边、清理折痕/杂线、对开页拆分、自动纠偏、断笔接续、接续档位（2.4.7 新增）、裁去白边，以及“处理分辨 / 单页体积 / 页面”这一行输出设置。

不保存的：导入的文件与处理结果。关掉页面就没了——这是有意的，文件太大，也不该占浏览器的存储配额。

几个边界：存储按“协议 + 主机 + 端口”隔离，用 8765 和 8766 打开是两套独立设定；隐私模式或浏览器禁用站点存储时保存会静默失败，功能照用、只是记不住；存档损坏或含非法值（手改过、旧版本残留）时按默认值降级，滑杆越界值会被夹回区间，下拉里不存在的选项会被忽略。「重置」会把全部参数（含开关与下拉）恢复默认，并把默认值存为下次的设定。想彻底清掉记忆：开发者工具 → Application → Local Storage → 删除 docscan.settings.v1。

六、参考的开源方案

算法思路参考了 ScanTailor Advanced（去底色 / 分页处理）、OpenCV 的四角检测与透视变换、Sauvola 自适应阈值论文实现，以及： 马健《ComicEnhancerPro》系列（先放大再二值化、墨量守恒、去除毛刺、MRC 分层）； 翁志艺《PDF 补丁丁》（重压缩的三条准入条件、页面尺寸与内容流分离、结构与渲染两层自检、按文件名生成书签）； 书格社区《智能图像预处理工具》与 ReadFree/HiPDA 的实操帖（Wolf 五档预设、形态学开闭去污、旧纸去底色）； ScanTailor Spectre（Picture/Fill Zones 的分区处理范式）。整个前端流程为自研 JS 实现，不依赖任何后端与 WASM。

2.4.6 复审时补查的成熟做法：ScanTailor Advanced 的「分阶段流水线 + 参数预设 + 前景/背景分层输出」印证了本项目 1bit 黑白层叠加彩色掩膜的路线；OCRmyPDF / unpaper 反复强调「默认保守、清洗不可抹掉印章与水渍、导出后要真的打开结果检查而不是相信成功提示」，对应本项目的全页回读自检；MDN 的 createWritable() 示例给出 try / close / abort 范式，用于修复写回失败时可写流悬空；二值形态学的「膨胀 3×3 与 / 腐蚀 3×3 或」通用定义用于重写印章掩膜的闭运算参考实现。以上都是思路与范式的借鉴，没有直接复制第三方源码；借鉴位置已在 pdfout.js、app.js 的 // modified 注释里逐处标注。

2.4.7 断笔接续专项调研（中文公文 / 仿宋）：① 线形结构元闭运算 strel('line', L, θ) 与 OpenCV MORPH_CLOSE 的中文预处理实践（MATLAB 文字区域检测、OpenCV 中文识别流程）指出横排文字宜取 0° / 90° 方向的细长核，比 3×3 方形核更少糊住笔画交叉处；② 笔刷算法（《自然场景下基于连通域检测的文字识别算法研究》）用 1D 横向游程桥接相邻笔画，本项目据此改为「四方向 1D 游程配对」而非全图膨胀；③ 骨架端点方向配对（《基于书写规则的书法字笔画及笔顺提取》、香港中文大学 Video-Based Handwritten Chinese Character Recognition 的双向图连接笔画段、K-P 算法用 PCA 判断点并以 B 样条重建）给出「先判走势、再补笔画」的判据，本项目的「两端各 ≥2px 实心 + 断口 ≤ 笔画宽度的一半」是它的轻量近似；④ CN122113840B 明确提到宋体 / 仿宋等衬线字体交叉处的微小间隙，并主张形态学核大小随渲染分辨率与平均笔画宽度动态调整，本项目据此用游程中位数估计笔画宽度；⑤ Leptonica pixCloseSafe 的文档影像边界约定（图外一律视为 OFF）用于确定扫描线在边界自然终止，不从图外「借」墨；⑥ ScanTailor Advanced / unpaper / OCRmyPDF 的保守默认值与「导出后真的打开检查」仍是本项目的底线。明确未采用：PaddleOCR 的 DB 可微分二值化、Real-ESRGAN 等生成式超分、字体重建与 OCR 矢量覆写 —— 它们或需要模型与后端，或会「预测」出原件没有的笔画（字形幻觉）；档案行业对生成式增强普遍持否定态度，与 DA/T 31 第 4.3 条「展现原貌」冲突。本轮同样只借鉴思路、没有复制第三方源码，出处标注在 core.js 的 bridgeGaps 上方。
